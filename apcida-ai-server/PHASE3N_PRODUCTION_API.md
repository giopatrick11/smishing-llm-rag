No Cloudflare route was created. Android `PRODUCTION_READY` remains `false`, and the SMS receiver has no production transport caller.** The old development and synthetic-pilot listeners still return 404 for `/api/v1/sms/analyze`.

## Architecture

The new `src/production/server.js` is a separate, opt-in listener. It requires all of `APCIDA_PRODUCTION_ENABLED=true`, `APCIDA_PRODUCTION_MODE=controlled-test`, and `APCIDA_PRODUCTION_BIND=127.0.0.1`; it binds to a distinct loopback port (default 3020), and cannot be started by the existing `npm start` or `npm run pilot:start` scripts. It also requires Gemma `gemma3:12b`, RAG, rules in shadow mode, Gemma verdict policy, the production schema, a private `PRODUCTION_DATA_KEY`, and the existing local Ollama/PostgreSQL prerequisites. It does not configure Cloudflare or expose an Internet route.

`POST /api/v1/sms/analyze` uses the Phase 3M strict contract and reuses the existing Ollama → pgvector RAG → shadow-rule analysis services. It sends only message ID, classification, confidence, and rationale back to Android. Pilot credentials, `pilot-` IDs, and the synthetic marker are rejected or unavailable on this listener. Requests have an 8 KiB JSON cap; validation, bearer authentication, persistent per-installation rate limiting, and an atomic global inference slot precede analysis. The local database pool has a 10-second statement timeout; the existing Ollama/embedding calls keep their 120-second per-call timeout. Model, embedding, RAG, and database errors return error codes, never a fabricated SAFE verdict.

A keyed HMAC of the normalized request binds `(installation_id, message_id)` to one payload without storing SMS text or sender. A first request takes an atomic PostgreSQL claim. Concurrent duplicates receive `REQUEST_IN_PROGRESS`; a different payload with the same ID receives `MESSAGE_ID_CONFLICT`. A completed response is replayed from AES-256-GCM ciphertext, including across listener restarts. Processing leases and the single global inference slot expire after 300 seconds if a process dies; an old lease owner cannot commit after a replacement claims it. Failed analysis removes its unfinished claim so a later explicit retry can proceed. A crash after Gemma finishes but before the database commit can still cause a later repeat inference; exactly-once execution across that boundary is not possible with this local model API.

## Identity and administration

`004_production_inference.sql` creates **separate** production installation, rate-window, request, and global-slot tables. It does not alter pilot identities, RAG records, or evaluation data. Routine `npm run db:migrate` now **skips this file by default**; applying it requires both `APCIDA_APPLY_PRODUCTION_SCHEMA=true` and `APCIDA_PRODUCTION_MODE=controlled-test` in an approved environment. An administrator must use the local-only `src/production/adminCli.js` with a distinct `PRODUCTION_ADMIN_KEY` and `APCIDA_PRODUCTION_ADMIN_TOKEN`; enrollment requires `--approve` and writes the unique 256-bit bearer token once to a new mode-0600 file outside Git. Only its SHA-256 hash is stored. There is no HTTP enrollment route. Tokens expire after 1–90 days (default 30). Expired/revoked/missing tokens receive a generic 401; an auth-store outage receives 503. Revocation is transactional: it marks the installation revoked and deletes its response cache and rate counters. The handler rechecks installation status before inference, before cached replay, and before returning a new verdict.

No administrator token or installation credential is embedded in Android. The Phase 3M Android production Keystore store is separate from the synthetic pilot store and remains unprovisioned.

## Privacy and retention actually implemented

- Routine request `text` and `sender` are passed to the local Gemma/RAG pipeline in memory. No production table has raw SMS or sender columns. The request HMAC is keyed with `PRODUCTION_DATA_KEY`; the response cache is encrypted with a separately derived key from the same 32-byte secret. Rationale may contain personal data despite the prompt, so it is encrypted at rest.
- The cache retention is configurable with `APCIDA_PRODUCTION_RETENTION_HOURS` from 1 to 72 hours, default **24 hours**. Expired entries are deleted at listener startup and hourly; an expired ID is also deleted on reuse. Actual deletion can lag expiry by up to one hour while the listener is running, or until the next startup if it was offline. Per-minute rate windows are deleted on the same schedule after the retention interval. Administrator revocation deletes that installation's cache and rate windows immediately in one transaction.
- Production installation rows (opaque UUID, label, token hash, issue/expiry/revocation times) remain for administrator status; there is no automatic identity-row deletion yet. PostgreSQL backups, filesystem snapshots, OS logs, Cloudflare logs, and Ollama process memory have separate retention behavior that is **not controlled** by this code. Those policies need review before real SMS. Android consent revocation does not currently notify the backend; cached responses therefore persist until TTL unless the administrator revokes the installation.
- Application audit events contain only event code, timestamp, and installation UUID. Error responses never include SMS, sender, bearer token, data key, or internal stack trace. The production listener has no raw request logger. Do not add raw headers/body to Cloudflare or reverse-proxy logs. Research contribution consent and storage remain separate.
