## Current architecture established from code

`A/backend/receiver/SmsReceiver.kt -> onReceive()` receives new SMS; `A/controller/SmsController.kt -> receiveAndAnalyzeRules()` deduplicates, runs `A/backend/detection/BackendKeywordRules.kt -> analyze()`, stores a provisional Room row, and posts a local warning for a rule `SCAM`. The Android rule result is `SAFE`, `SUSPICIOUS`, or `SCAM`, but `A/backend/network/RemoteVerdictPolicy.kt -> localFallback()` maps rule `SAFE` to user-facing `UNVERIFIED` until remote verification. `A/backend/worker/SmsProcessingWorker.kt -> enqueue()/doWork()` submits **eligible new SMS regardless of rule score** to the authenticated server, only when the beta build gate, enrollment/credentials, HTTPS host, and AI Protection consent pass (`A/backend/remote/ProductionRemoteRuntime.kt`; `A/backend/network/RemoteTransportGate.kt`; `A/backend/consent/AutomaticAnalysisPolicy.kt`; `.tmp-mobile-notification-fix/app/build.gradle.kts`). Historical SMS require a separate participant-approved small batch (`A/backend/worker/HistoricalSmsBatchWorker.kt`). Debug and ordinary release builds leave this automatic remote route closed by default.

`A/backend/remote/ProductionSmsTransport.kt -> analyze()` sends `messageId`, sender, **raw SMS text**, and `receivedAt` to `POST /api/v1/sms/analyze`. `S/production/createProductionApp.js -> createAnalysisService()/createProductionApp()` requires server `gemma3:12b`, RAG, and rules enabled; its live inference chain computes **shadow** server rules, embeds SMS with `nomic-embed-text`, retrieves approved examples from PostgreSQL/pgvector, and calls Ollama Gemma 3 12B with those examples (`S/services/hybrid.js`, `S/services/rag.js`, `S/services/embeddings.js`, `S/db/knowledgeRepository.js`, `S/services/ollama.js`). With `shadowMode: true` and `verdictPolicy: 'gemma'`, server rules are recorded for comparison but do not change the Gemma verdict (`S/services/verdict.js -> resolveVerdict()`). The returned `SAFE`/`SUSPICIOUS`/`SCAM`, confidence, and rationale become the verified mobile result (`A/controller/SmsController.kt -> applyRemoteResult()`). If remote work fails, the app retains the provisional warning or `UNVERIFIED`, not a fabricated Gemma result (`A/backend/remote/AutomaticRemoteCoordinator.kt`; `A/backend/network/RemoteVerdictPolicy.kt`).

The **debug-only** MediaPipe path loads `gemma3-1b-it-int4.task` on demand and parses `SCAM`/`LEGITIMATE` (`AD/backend/gemma/GemmaValidator.kt`; `AD/backend/gemma/GemmaManager.kt`; `A/backend/gemma/GemmaOutputParser.kt`). It is historical/local evaluation functionality, not the supervised beta detector: MediaPipe is `debugImplementation` only (`.tmp-mobile-notification-fix/app/build.gradle.kts`). The source still contains a legacy `RiskScorer`, `ThresholdEvaluator`, XML keyword seeding, and `FinalVerdictResolver`; the current SMS intake directly invokes `BackendKeywordRules`, so do not attribute the legacy path's scores or model policy to beta intake (`A/controller/SmsController.kt`; `A/backend/detection/RiskScorer.kt`; `A/backend/database/DatabaseSeeder.kt`).

On-device storage is Room/SQLite database `kasds_database`, schema version 9, five entities (`A/backend/database/AppDatabase.kt`). PostgreSQL stores approved RAG examples, protected inference cache and installation control, encrypted user reports, and optional study records (migration files under `S/db/migrations/`). Routine inference request bodies are not inserted into PostgreSQL; a keyed HMAC and encrypted response are cached (`S/production/privacy.js`; `S/production/repository.js`). User reports **do** persist encrypted SMS text for review; they do not automatically enter RAG (`S/production/reportContract.js`; `S/production/createProductionApp.js`; `S/db/migrations/007_production_reports.sql`; `S/production/reportReviewCli.js`; `S/knowledge/batchReview.js`).

## Evaluation and methodology audit

**Completed committed development evidence.** `dataset/apcida_synthetic_sms_200.csv` has 200 rows (100 scam/100 safe in result matrix); `evaluation-results/baseline-200/evaluation.json` records 200 valid Gemma 3 12B predictions, scam warning recall 100/100, safe warning rate 7/100, median 10,232.5 ms. `evaluation-results/rag-200/evaluation.json` on the same 200 rows records 197 valid/3 errors (1 Ollama timeout, 2 RAG database unavailable), scam warning recall 99/100, safe warning rate 5/98, median 12,298.5 ms. These older two-class datasets have **three-way outputs** and the published “binaryAccuracyDecisive” excludes `SUSPICIOUS`/errors; do not quote it as whole-set accuracy. The 50-row development, holdout and mode comparisons are recorded in `evaluation-results/phase2e-*`, `phase2f-*`, `phase2g-*`; e.g. holdout `phase2g-gemma-rag` had 48 valid/2 timeout and 46/50 exact, versus `phase2g-gemma` 48/50 exact with no error, while `phase2g-hybrid-rag` had 49 valid/1 timeout and 48/50 exact. `evaluation-results/phase2f-rules-development/evaluation.json` gives 50/50 on a **development** split and must not be presented as a generalization estimate. `evaluation-results/rules-v3-targeted-regression/report.json` explicitly labels its 18 hand-picked cases as non-held-out. The 8-case three-class exploratory report has ground-truth support SAFE 4, SUSPICIOUS 2, SCAM 2; audited exact accuracy is 6/8 rules, 6/8 Gemma, 7/8 Gemma+RAG/shadow, and macro F1 is 0.556/0.730/0.822 respectively (`evaluation-results/three-class-exploratory-v1/audited-report.json`). This is a small diagnostic, not final thesis validation. `S/evaluation/threeClassMetrics.js` supports per-class precision/recall/F1, macro F1, confusion matrix, warning rate, and latency; `S/evaluation/metrics.js` supports older binary-ground-truth summaries. `S/evaluation/ragInvestigation.js` and committed `evaluation-results/rag-investigation-2026-11-13-v3/report.json` examine retrieval, not a participant outcome.

**Code-supported but not established as completed participant evaluation.** Optional study contribution endpoints, encrypted storage, independent expert label workflow, and model/RAG snapshot checks exist (`S/production/createProductionApp.js`; `S/study/contract.js`; `S/study/worker.js`; `S/db/migrations/009_study_contributions.sql` and `010_unlabeled_study_contributions.sql`). No committed participant response-rate, usability survey, real-world confusion matrix, or final thesis sample size was found. The manuscript's Gemma Invocation Rate formula (§3.9, p.47) assumes keyword-triggered inference; beta submission is eligibility-based instead. Its Contextual Override Rate assumes a rule verdict overridden by on-device Gemma; server shadow rules do not alter beta final verdict, though separate experimental `runHybrid.js` records corrected/introduced errors. Re-specify both metrics or remove them for the beta. Usability, accessibility, perceived usefulness, real-world false-negative rate, and device resource use remain planned unless separately documented.

**Testing observation.** The repository includes 32 server `.test.js`, 35 Android unit `.kt`, and 9 Android instrumentation `.kt` files (source inventory). `npm test` was attempted; tests requiring a loopback listener failed with `listen EPERM: operation not permitted 127.0.0.1` in this sandbox, so this audit does not treat that run as an application failure. No Android/DB/live inference test was run for this document.
